# Main mod menu (PgDown): shell + tabs

Full-screen window. Chrome (background, icon rail on the left, header) = `UI/Menu/BtcMenu.cs` (static `BtcMenu`: `DrawBackground`, `DrawHeader`, `DrawRail`, `DrawTip`, colours `Accent/Bg/RailBg/Line`).
Entry: `ResourcePackManager.DrawMenu` (C02) -> shell chrome -> content. Tab selection: `ResourcePackManager.SelectTab(id)` (`ResourcePackManager.Menu.cs`).

## Tab ids (stable)
0 Packs, 1 Overlays (HP), 2 BetterConnection, 3 Hotkeys (`BtcHotkeysUI`), 4 Gameplay (`BtcGameplayUI`), 5 Share (`BtcShareUI`), 6 Profile (`BtcNick`), 7 Replay, 8 Duel (`BtcDuelUI`). 9 Report a bug, 10 What's new. Rail icons: `BtcMenu.IconOf`.

## New architecture (migrated tabs)
- One class per tab: `abstract class BtcMenuTab { Id, IsActive, Draw(Rect area, int fs) }`. The tab owns its scroll view and state; the shell already drew the background and the header.
- Register in `BtcMenu.EnsureRegistered`. `DrawMenu` calls `BtcMenu.ActiveTab()` before the legacy scroll view; if non-null it draws the tab and returns.
- Migrated: Replay (`Replay/BtcReplayTab.cs` -> `BtcReplayUI.Draw` settings + `BtcReplayLibrary.Draw`).
- To migrate a legacy tab: add a `BtcMenuTab` subclass (move the body of its static `Draw(Event,w,rowH,fs,color)` into it), register, delete its branch in the legacy if-chain in C02 (search `TabActive`).
- Legacy tabs 0-2 still live inside `ResourcePackManager` (partial, C01..C16); do not add new tabs there.

## Shared look (use for new tabs)
Flat dark panels, 1 px `Line` separators, `Accent` for the active/selected thing, icons from `Replay/BtcReplayIcons.cs` (procedural, add a `case` + id), tooltips via `BtcReplayIcons.Button/Plain` + `DrawTip(fs, maxX, below)`, font = `BtcReplayUI.sBarLabel`. No frames around images, no menu-style buttons.

## Undo (Ctrl+Z) - RULE for every tab
- Each tab names an undo scope: `internal override string UndoScope { get { return "hotkeys"; } }` (Hotkeys "hotkeys", Replay "replay"; a new tab picks its own). The shell (`BtcMenu.HandleUndo`, called from C02 before the tab draws) turns Ctrl+Z into `BtcUndo.Undo(scope)`: reverts the newest step, plays a sound and shows "Undone: <what>" with the undo icon at the bottom (`BtcMenu.Toast`). Unlimited steps (200 per scope), not while a text field or a key capture has focus.
- Every change the user can make by accident MUST push a step: `BtcUndo.Push(scope, label, undoClosure[, mergeKey])` (mergeKey folds a drag / typing burst into one step), `BtcUndo.Group(scope, label, body)` folds several changes (a profile touching mod + vanilla binds) into one. Switch rows: `BtcUi.ToggleUndo(ref y, w, fs, scope, label, value, hint, setter)`. Changes made inside an undo closure are not recorded (`BtcUndo.Suspended`).
- Deletes must be reversible: move to a trash (replays: `Replays/.trash`, 14 days) or keep the content in the closure (profiles). Hotkeys records in `BtcHotkeys.SetRaw/SetFloat/RecordAll`, vanilla binds via snapshots of userconfigs.lua (`BtcVanillaBinds`).

## Rules learned (Visuals tab, user feedback 2026-11-10: READ before migrating any tab)
- MASTER SWITCH: ONE switch in the page header (right side, next to the Simple/Expert icons) on every page, never a row inside a section/fold (the "world overlays" master once landed inside the first overlay's fold because the legacy feature drew it in its own DrawSettings: remove such rows from the feature draw code, `false && check(...)`, and own the switch in the tab). Several feature masters can share one header switch: it is ON if any is on, off turns all off, ON again restores the previous states.
- Simple/Expert: the stored flag is the INVERSE trap: `BtcUi` folds remember CLOSED keys, so `visual:simple` "open" (default) = Simple mode; Expert = `!IsOpen`. Gear icon sets `SetOpen(false)`, eye icon `SetOpen(true)`. Buttons already play the switch sound: do not call `BtcSfx.Switch` on top.
- Hover sound: `BtcSfx.Hover` has a 0.1 s cooldown because overlapping controls under the pointer alternate their hover key every frame ("machine gun"). Avoid overlapping Btn rects anyway; draw sub-buttons (stars, trash) BEFORE the full-row button.
- Favourites: `BtcVisualRows.Star(rect, key, label)` + `Favs` list (file visual-ui.txt, `fav=key`), star in a right gutter (`GutterW`, `StarRect`), also on fold headers and palettes; a Favourites page lists starred settings (drawn with `Setting()`) and starred sections as jump links. Reuse this for other tabs (copy the pattern, use own key prefix + file or a shared store).
- "All" page: flat, no section headers: set a `_flat` flag so `FoldF` draws nothing and call every page body in order.
- Registry pattern: for a tab with many settings declare each once (key, page, section, EN/RU, getter/setter with side effect) and draw/search/undo/export generically; for legacy features with `DrawSettings(check, step, slider, color)` callbacks, supply new-style callbacks (`BtcVisualRows.Check/Step/SliderCb/ColorCb`) instead of rewriting them (undo of those = replayed click / old value on the next draw).
- IMGUI traps: lambdas cannot capture `ref` params (copy `y` to a local and write it back); a scroll view's mouse is local, so register text-field rects for click-away with `GUIUtility.GUIToScreenPoint`; PgDown inside a focused field needs the PgDownFrame trick (see tab Draw start).
- Tooling traps: NEVER use `perl -pi` with `$` text or Cyrillic in replacement for files you did not just create without re-checking (a perl replacement corrupted BtcSfx.cs once, restored with git checkout); prefer the Edit tool. Russian only through Write/Edit.
- DEV test of a tab: add a `visualtest`-like scenario command (see `visual-ui`), run `scripts/scenario.ps1 -Name ...`, look for `[VisualDev] drew page`; the agent cannot judge visuals, the user does.
