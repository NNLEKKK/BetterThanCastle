# Melee attack mechanics (vanilla), spec for a headless simulator
Sources (ref/vanilla/Brix/Game/...): AI/Nodes/AttackInfo.cs ("A:"), Locomotion/Striking.cs, AI/MeleeAttack.cs, MeleeWeapon.cs (ref/vanilla root), AI/Profession.cs, AI/CharacterLocation.cs, AI/Damage/BricktronDamageReceiver.cs, LaborInstinct.cs (root), AI/Order.cs.
Tick = one behaviour-tree / FixedUpdate step = 20 ms (A:`WaitForTicks(50)` is labelled "at least 1 second"). Halberdier stats (HP 500, dmg 32) are our measurements (docs/duel-bot-research.md:6); prefab values are NOT in the decompile.

## 1. AttackInfo state machine
1. One AttackInfo per order (pooled). `ResetObject` (A:231-253) zeroes CurrentFrame, NextAttackFrame=0, NextMeleeTargetFrame=0. Every order (GoAttack*, MoveAttack, HoldPosition*) runs Reset then Work => fresh state: the first strike of a new order is allowed at once (no cooldown memory). This is the skip exploit.
2. Per tick two parallel loops (A:`MainLoop` ~366): ObservationLoop = `FindBestTarget(false)` then `NextFrame()` (CurrentFrame++, A:786); ActionLoop = selector: `HasCombatAction` -> DoCombatAction; else `HasRunDestination` -> run toward destination; else wait.
3. `HasCombatAction` (A:480): true while MeleeTarget or RangedTarget != null; after both are lost it stays true for 11 frames (NoActionEndFrame = CurrentFrame+max(5,10)+1) before falling back to running to the destination.
4. `FindBestTarget` (A:~810): forced once at MainLoop start, then whenever CurrentFrame >= NextMeleeTargetFrame; period 5 frames (both ternary branches are 5). Skipped (target kept) when the current target is a Labor and WantStrike is set. CanAttackMelee = Profession.HasMeleeAttack() (MeleeDamage != 0) && Interaction.CanStrike().
5. Target search `FindBestMeleeTarget` (A:~905): breadth-first PATH search on the walk graph from own cell. Horizontal radius `MeleeSearchRadius` (dx^2+dz^2 <= R^2): GoAttack*: 3; MoveAttack/WalkMoveAttack: 10 (A:361,375); if CanMove=false (Hold*): 2 (A:1285). Visit limit `MeleeSearchLimit`: 30 default, 200 for MoveAttack. Climbing allowed, no voxel breaking. `PresenceTest`: cells with obstacles or ANY character volume are blocked (A:1038-1056), so units path around others and an enemy behind another unit may be unreachable.
6. Accepter `EnemyAccepter._Visit` (A:1370-1430), per visited cell holding an enemy (faction IsEnemy), first success wins: (a) enemy == DestinationTarget -> chosen at once; (b) AttackDestination==MustAttackDestination (GoAttackDirectly, HoldPositionAndAttackDirectly) -> any other enemy rejected: it fights ONLY its order target; (c) CombatPriority >= AttackOnSight -> chosen at once (assumption: units are this class, verify); (d) AttackHighPriority remembered if higher than current; (e) enemy blocking the path remembered; (f) PrioritizeDestination with a destination target -> skip the rest; (g) AttackLowPriority and visible to faction -> first one remembered. NO distance/HP scoring: the target is the first enemy in BFS order (nearest by path steps). Not sticky: re-evaluated every 5 frames, so it flips as units move (except Must/Destination target).
7. `FindBestMeleeAction` (A:~560): WantStrike=true if `CharacterLocation.TargetReachedOrAcceptable(self, PresenceOccupied, targetCell)`, else if true from the cell being ENTERED (PositionEnteringOrOccupied); WantStrikeFrom/To = those cells. Otherwise WantStep if a StepBranch exists (combat step toward the target).
8. Reach in VOXEL cells (CharacterLocation.cs:95-121). `TargetReachedOrAcceptable = IsInVeryCloseRange || TargetReached`. VeryClose: flat Manhattan(dx,dz) <= 1 and |dy| <= 1 (includes same cell). TargetReached: flat sqr dist in [0.81, 4.41], i.e. (dx,dz) with dx^2+dz^2 in {1,2,4} = offsets (1,0),(1,1),(2,0); NOT (2,1)=5; |dy| < 1.1 (<=1); and for sqr >= 1.21 (diagonal and 2-cell) no obstacle in the line (`CountMutualLibertes(..., Climbing) != 0`). Grid-quantised, not float distance.
9. `DoMeleeAction` (A:598-700), each tick when a target exists. Reads locomotion flags: IsReadyToStrike (animator state ReadyToStrike, ReadyToStrike.cs:14), InCombatStance, Striking = Cranking||Swinging||Reacting, Turning, Halting, IsGrounded. If Striking: IsPreparingToStrike=0; else if >0 decrement. Not grounded -> nothing.
   Strike branch (`WantStrike || Striking || IsPreparingToStrike>0`):
   - if IsReadyToStrike && CurrentFrame >= NextAttackFrame: IsPreparingToStrike=10; at=(From+To)/2 (integer voxels); if at.Flatten()==From.Flatten() or ==To.Flatten() (adjacent offsets: midpoint truncates onto one end) or `PassThroughDoor(at)` -> `Strike()`. Diagonal / 2-cell reach strikes only if that midpoint test passes (unknown how often; measure).
   - else if !InCombatStance: IsPreparingToStrike=10, `Wield(null)` (draw weapon, enter stance) and `ClearPath()`.
   - else (in stance, cooldown not over, or not ready state): nothing, wait.
   WantStep branch: if !CanCombatStep (needs CanMove && (ListenToRangeInstinct || destination is SpaceLocation/none || MustAttackDestination)): enter stance, or `DoCombatTurnTo(target)` if facing angle >= 45 deg (`IsInPreferredOrientation`, A:~893) and not striking; else if in stance `GetReadyToMove`; else `DoFollowStrikePath` (up to 4 step nodes).
10. `Strike()` (A:793): `Locomotion.DoStrike(target DamageReceiver, WantStrikeFrom)`; `NextAttackFrame = CurrentFrame + Profession.RandomizedAttackCooldown`. The cooldown counts from strike START, not from damage. `RandomizedAttackCooldown = AttackCooldown + Random.Range(-AttackCooldownRandomness, +AttackCooldownRandomness)` (Profession.cs:147; int Range, upper bound exclusive; with randomness 0 it is exactly AttackCooldown). Field defaults: `AttackCooldown = 75` (Profession.cs:1288) = 1.5 s, `AttackCooldownRandomness = 0` (:1291); the prefab may override (measured halberdier full cycle 1.5 s, DuelPatches VanillaCycleMs=1500). Level scaling: `AttackCooldown = round(prefabCooldown / (1 + 0.3*(level-1)))` (:180, :1100); level 1 => x1.
11. Ranged branch irrelevant for halberdiers (CanAttackRange false).

## 2. Strike -> damage timeline (Striking.cs)
12. `DoStrike` -> `Striking.Strike`: `MeleeWeapon.CreateAttack` (damage frozen NOW from MeleeDamage), phase Startup. Animator: Crank (`StartCranking`, IsCranking) -> Swing (`StartSwinging`, IsSwinging) -> Reacting (`StartReacting`, IsReacting). **Damage is applied in `StartReacting`: `SwordStrike.Apply(Target)`** (animator transition into follow-through). Measured strike-start -> damage ~450-480 ms = ~23-24 ticks (docs/duel-bot-research.md:7). Crank/swing durations are animator clip lengths, not in code: measure.
13. Checks during crank/swing: each tick `IsStrikeTargetValid()` = target not null/released and `Vector3.Distance(target, self) <= 9.5` world units (NOT the reach; almost always true). Invalid -> `IsAbortingStrike` -> `StartAbortingStrike` (strike dropped, no damage, AttackFailed fired, cooldown NOT refunded). NO distance or facing check at damage time: `MeleeAttack.Apply` (MeleeAttack.cs:80) just calls `Target.ReceiveAttack`. A target that stepped away but is within 9.5 m still takes the hit (consistent with lab duel-dodge). During crank/swing the attacker is moved toward `StrikeEndPosition` (= WantStrikeFrom cell) by `MatchTarget` (norm. time 0.1-0.9) and rotated toward the target; `WantsStop` re-snaps it to its occupied cell.
14. Target dead before StartReacting: if released, Apply is skipped (strike nulled anyway); a dead but unreleased corpse would still get ReceiveAttack (unknown, measure). Overkill therefore wastes the strike.
15. Defender (`BricktronDamageReceiver.ReceiveAttack`, :370; reaction :249): melee expected reaction = Twitch (AttackTemplate.DefaultMelee, AttackTemplate.cs:40-45), Smash if MeleeWeight >= 5 (MeleeWeapon.cs:19). Unwavering turns Stun/Twitch into Endure. `CanBlockAttack` (:404) -> Block (unless Smash): needs stamina >= RequiredStaminaForShieldBlock (1.0), Profession.CanBlock(), (if not Defending) type Melee and `Locomotion.IsReadyToBlock()` and not (cranking && stamina < 2.5), and attack force within `BlockingAngle` of the defender's back vector (frontal arc). Block: damage*(1-_meleeBlockResist), absorbed by stamina first (:290-305), remainder to HP. Else `value >= CurrentHP` -> Die. HP -= `ApplyResistances(value,type)`. Hurt reactions: Twitch->SmallHurt, Stun->BigHurt, Block->DoStartBlocking(0.5), Smash->Smash; they presumably interrupt the defender's own crank/swing (MEASURE: key for trade rules). Whether halberdiers CanBlock is profession-specific (not yet read: Profession.CanBlock).

## 3. Orders and the skip
16. `GoAttackDirectly` (Order.cs:530 -> A:260): Destination=target, MustAttackDestination: attacks ONLY that target (radius 3, limit 30); when not in reach it runs toward it (`RunTowardDestination`, run if CanRun). `GoAttack`: DontPrioritize (any enemy found nearby can take over). `GoAttackWithPriority`: Prioritize. `HoldPositionAndAttack*`: CanMove=false, radius 2. `MoveAttack(Location)` (Order.cs:519): SpaceLocation destination, radius 10, limit 200: auto-acquires the first enemy by BFS within 10 cells (rule 6c), fights it (CanCombatStep true), and resumes running to the point after 11 frames without target. `Order.Move.RunToward` (Order.cs:278) = plain `labor.RunToward`, no AttackInfo: no attacking while it runs (instinct preemption not verified).
17. A new order replaces the running tree: the old AttackInfo is disposed and the new one starts at CurrentFrame=0, NextAttackFrame=0. The animator swing is a separate state machine in Locomotion4: it survives the order unless the new order's locomotion calls (Drop/ClearPath/Wield/run commands) reach the animator before the swing commits. Measured: an order < ~8.5 frames after strike start cancels the strike (no damage); the mechanism is in the animator graph, not in code.
18. Our skip (BtcDuelBot.SkipTick, BtcDuelBot.cs:100-118): K frames after `StrikeFrame` (DuelPatches NextFrame Postfix :86-97, K>=9 so damage is not cancelled) send MoveAttack(own position) then Attack(target): the move-attack ends the follow-through recovery, the new AttackInfo has NextAttackFrame=0 so the next strike starts immediately. Vanilla cycle 1.5 s, realistic with skips 1.1-1.2 s, ideal 0.585 s. Without skips DuelPatches cycle guard (:40-59) blocks Strike for 75 frames (-15 ms) per unit.
19. Idle auto attack: `LaborInstinct` tree (LaborInstinct.cs:76) runs `FightableEnemy` every 10 ticks (0.2 s) over `GetClosestEnemies(GetAggroDistance(true))`; aggro distance = 3 if `!Autonomy.ListenToRangeInstinct` else `Profession.AggroDistance` = visionDistance stat + `BaseAggroRange` 25 (Profession.cs:1160,1285; Labor.cs:869). Per enemy (CombatPriority >= AttackLowPriority, not invincible): if melee `TargetReached` (item 8) from current position and ListenToMeleeInstinct and HasMeleeAttack -> Close; else if ListenToRangeInstinct and (projectile or IsStrongInMelee) -> Ranged. Package: Close -> `HoldPositionAndAttackWithPriority` (DecisionSource.Character); ExtendedRange+StrongInMelee -> `GoAttack`; AttackOnSight -> `GoAttackWithPriority`; else `GoAttack`. Autonomy: FreeAgent/LockedToOperable/InstinctOnly listen to both, HoldingPosition melee only, WaitForOrders none (AutonomyStatus.cs:335-526). So an idle default-autonomy unit auto-engages an enemy in melee reach, and chases enemies within aggro range if strong in melee. Whether Character-source packages preempt a User order: Labor.SendOrder/DecisionSource (Labor.cs:1238), not read.

## 4. Numbers
20. `Profession.MeleeDamage` (Profession.cs:1069) = `RoundToInt( max(toolStat meleeDamage, base) * CombatRules.UnitToUnitDamageMultiplier * (1 + 0.2*max(level-1,0)) )`, base 18 for Arbalist else 12. The halberd stat comes from the Poleaxe tool prefab (`Adjectif.meleeDamage` via toolbag); Grep "Poleaxe" in ref/vanilla yields only asset keys, no numbers. `UnitToUnitDamageMultiplier` is set by Lua `Rules.unitToUnitDamageMultiplier` (CombatRules.cs:43; ref/lua/gameplayTest.lua:1 = 1.0). Measured hit = 32 at x1, HP 500 => 16 hits to kill (15.6 rounded up), unblocked.
21. `MeleeWeight` = max(meleeWeight stat, 1) = ForceFactor (knockback strength and block-angle test), Smash at >= 5. `MeleeWeapon.Range = 2` exists but is not used by AttackInfo (reach is hard-coded, item 8).

## 5. Facing and multiple attackers
22. Facing: no strict angle gate for starting a strike. Turning to the target happens only in the WantStep branch (angle >= 45 deg -> `DoCombatTurnTo`). The strike animation itself rotates the attacker toward the target (`MatchTarget(CombatCrank/CombatSwing, ..., LookRotation(targetFlat - StrikeEndPosition), 0.1, 0.9)`, Striking.cs). `StrikeDistance` anim parameter = InverseLerp(1.4, 2.0, flatDist) selects the short/long clip (not reach). Turn speed: `TurningTo` state, not read: measure deg/s.
23. Multiple attackers: no slot or strike-spot system. Limit is spatial only: an attacker needs a free reachable cell within reach (character cells are blocked for the search), so at most the free cells of the reach ring: 8 adjacent + 4 at distance 2 = 12 geometric, minus occupied/terrain. Damage from several attackers simply adds.
