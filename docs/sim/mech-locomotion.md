# Mechanics: halberdier movement, pathing, melee approach (spec for headless sim)
Sources: V = ref/vanilla (paths relative to ref/vanilla/Brix/Game unless noted). `Brix.Core`-style framework is IN ref/vanilla (Motus/Behavior/*), nothing missing except XYZ/PathNodeRegistry/pathfinder internals (not found in ref/; see Unknown).
Companion: docs/sim/mech-damage.md (hit pipeline, cooldown).

## 0. Time model (who ticks when)
1. AI/behaviour trees (Labor tree, AttackInfo subtree, Navigation nodes) tick in `Behavior.BrixFixedUpdate -> Tick -> TreeRun.Run()` (Components/Behavior.cs:35,59-70), driven by `GameClock.FixedUpdate -> FixedUpdateSig` (GameClock.cs:153-157). So 1 "tick" = 1 FixedUpdate (Unity default 0.02 s = 50 Hz; fixedDeltaTime itself is a ProjectSettings value, not in V; code assumes it, e.g. NavigationNodes.cs:83 `duration / Time.fixedDeltaTime`). `Node.WaitForTicks(n)` = TickCondition: `TickToWaitLeft-- <= 0` (Motus/Behavior/TickCondition.cs) -> waits n+1 ticks.
2. AttackInfo.CurrentFrame is incremented ONLY in `ObservationLoop` (AI/Nodes/AttackInfo.cs:463-464 `NextFrame()` -> `CurrentFrame++` :789-791), a Sequence loop in a Parallel with ActionLoop, executed once per FixedUpdate tick. CurrentFrame resets to 0 on Reset (:242). => attack cooldown units (Profession.AttackCooldown default 75 frames, Profession.cs:1288, minus randomness `AttackCooldownRandomness`, :147-152; level divides it, :180) are FixedUpdates (75 = 1.5 s at 50 Hz).
3. Locomotion (position/rotation/animator state machine) runs per RENDER frame: `Locomotion4.BrixUpdate` (AI/Locomotion4.cs:420-458) with `Time.deltaTime`; it is registered via GameClock Update (not FixedUpdate). Movement is therefore frame-rate dependent in sampling but speed-constant (see 1.3). In a headless sim use a fixed dt (0.02) and treat as the continuous limit.
4. Order of events within one Locomotion4 frame (:420-458): `targetMatcher.Time = Time.time`; `AnimatorUpdate` signal (state `Update()` e.g. Running.Update -> Move -> OverrideMatchTarget); then `ManualUpdate(dt)` = `targetMatcher.AnimatorUpdate(dt)` (Time += dt) + `AnimatorMove` signal -> `ApplyAnimatorMotion` (:1227-1231) -> `SetPosition`. If the current override ends inside this frame (`OverrideTimeOfEnd` in [Time.time, Time.time+dt)), the frame is split at that instant (min slice 0.001 s) and `AnimatorUpdate` re-runs for the remainder, so waypoint arrival does not waste time.

## 1. Locomotion4 / how a unit actually moves
1. Movement is CODE driven, not root motion, for run/walk/halt/turn/combat-step/strike: `TargetMatcher` "ManualOverride" mode (AI/TargetMatcher.cs:ConsumePosition/OverrideMatchTarget). Animator root motion (MatchState Matching/Waiting) is only used for climb/hurt/stabilize/strike-crank clips (Striking.cs:44,69; Hurting.cs:12-18; Airborne.cs).
2. Position each frame: `pos = Lerp(origin, target, (Time-start)/(end-start))`, with `start=Time` set the same frame by the state's `OverrideMatchTarget(time=dist/speed, ...)`. => displacement per frame = `speed*dt` along the straight line to the current target; if `dt >= dist/speed` it snaps to the target. I.e. constant speed `SpeedMperS`, instant start, no acceleration, no deceleration during cycle (verified: LocomotionWalkableCycleState.MatchTargetWithSpeed :~95-103: `time = |target-pos| / speed`). Y follows floor (SnapToFloor :1260-1279, `IsSnappable`: |dy|<=1.5 or same rounded y).
3. Rotation per frame: `rot = Quaternion.Lerp(origin, targetRot, dt / rotationTime)` with `rotationTime = min(moveTime, angle / (TurningTopSpeed*360))`. Run: `RunTurningTopSpeed = 1` => <= 360 deg/s (Running.cs fields; Walking `WalkTurningTopSpeed = 1`). Short angles finish together with the move leg. The unit turns WHILE moving (no stop-to-turn); target yaw = `LookRotation(flat(target - pos))` each frame (:99-101).
4. Which target point: `GetCurrentTarget` (LocomotionWalkableCycleState.cs:~125-140). With a = voxel of position, b = Current path node, c = next node: `target = ((a+b)/2 + (b+c)/2)/2 = (a+2b+c)/4`. On a straight line this equals b (next voxel centre); at 90-degree corners it cuts the corner (target between edges). Special case: corner AND steep (3 different y) uses an offset; not relevant on a flat plateau. Voxel centres = integer coordinates (x,z; edge point is (a+b)/2).
5. Path iterator advance: every frame `FastForwardPath` (LocomotionMovementState.cs, ~:230-250) scans from CurrentIndex-1 forward and `MoveNext`s to the node whose voxel (x,z equal, |dy|<=1) equals the unit's current voxel (`XYZ.FromVector3(trf.position)`; almost certainly rounding to nearest int, XYZ source not in ref - see Unknown). So the unit "passes" a node when its position rounds into that node's voxel (i.e. ~0.5 m before the centre), then aims at the next.
6. Speeds (serialized prefab defaults in the class; prefab may override, MEASURE): Run `RunSpeedMperS = 6`, Walk `WalkSpeedMperS = 3`, `RunArriveSpeedMperS = 2`, `WalkArriveSpeedMperS = 2`, `CombatStepSpeed = 5` (Stepping.cs), `TurnOnSpot.TurningSpeed = 2` (=720 deg/s, TurnOnSpot.cs:64). Running.cs: `RunSpeedStrikeBonus = 3`, `RunArrivalDistance = 1`, `RunAbruptStopDistance = 0.75 (set to 0.1 on Enter)`.
7. Level multiplier: `Profession.CharacterLevel` setter (Profession.cs:~165-182): `Walk/RunSpeedMperS = prefabValue * (1 + max(level-1,0)*0.3)` (MovementSpeedLevelMultiplier :1090-1096; prefab = `Factory.Peek(AssetKey).GetComponent<Locomotion4>()`). Level 1 -> x1.0. Job change (`Occupation.OnJobChange`, Occupation.cs:62-66) overwrites RunSpeed with prefab + `Profession.JobSpeedBonus` (0 for non-Builder, Profession.cs:184-). Arbalist sprint x1.65 only (Running.cs SpeedMperS). There is no separate "Profession move speed stat" for halberdiers beyond this.
8. "Strike run" bonus: when `IsInStrikingPath` (combat step path), run speed = `RunSpeedMperS + RunSpeedStrikeBonus * clamp01(1 - distToDestination/4)` (Running.GetStrikingRunSpeed) -> 6 .. 9 m/s while closing in the last 4 m of a strike path.
9. Run vs walk choice at path start (InPlace.Update, Locomotion/InPlace.cs ~:75-90): `CanRun && Peek exists && Peek.IsWalkable && !IsAdjacent(position, Peek.Position)` -> Run; else Walk. I.e. paths with 0-1 remaining nodes beyond the current one (or where the 2nd node is adjacent to the unit) are WALKED at 3 m/s. Walking.Update upgrades to Run as soon as Peek exists and walkable and not in animator transition (Walking.cs:~96-100). Running.Update downgrades to walk only if `!CanRun` (AttackInfo.WalkMoveAttack).
10. Arrival: when `PathIterator.HasCurrent == false`, `Stop()`: Running.RunStop (Running.cs:~108-135): destination = `RoundVecteur(position)` (voxel centre), time = flatDistance / `RunArriveSpeedMperS (2)` (or striking speed), i.e. decel is a final slow slide of < 0.5 m to the voxel centre at 2 m/s (<= 0.25 s), also rotates to node orientation if it has one. `IsRunCycling=false` triggers animator InPlace later (animator transition delay = unknown clip timing). Walking.WalkStop likewise at 2 m/s.
11. Blocked by a unit/obstacle at the next voxel (`TryPushingForward`): see 3.

## 2. Orders -> movement on flat ground
1. `Order.Move.RunToward(Location)` = `labor.RunToward(loc, precise=true, aggressive=false)` (Order.cs:278; Nodes/NavigationNodes.cs:52) -> `NavigateOrBreakYourWayTo` (:126) -> `_NavigateTo` -> `Navigation.NavigateTo(location, exact, precise, aggressive)` (Navigation.cs:44). Search = A*-like `SearchPathRequest` (`SearchPerUpdate = Autonomy.PathfindingBudget`, async across ticks; result = list of WalkNodes, voxel-to-voxel). Success -> `FollowPathRequest` -> `Locomotion.DoFollowPath(path)` (FollowPathRequest.cs:~110). Fail -> `Tries.CountFailureAndWait(50)` (50 ticks) and retry; `PathFailed(...)` -> `WaitFor.Ticks(20)` (Navigation.cs:132).
2. `MoveAttack(SpaceLocation)` (AI/Nodes/AttackInfo.cs:~340): `Destination = location; MeleeSearchRadius = 10; MeleeSearchLimit = 200` (defaults 3 / 30). `WalkMoveAttack`: also `CanRun=false`. `GoAttackDirectly(target)`: `Destination = Location.Of(target); AttackDestination = MustAttackDestination` (never gives up on that target; `MustWait()` :476). `GoAttack`/`GoAttackWithPriority` differ only in AttackDestination (Dont/PrioritizeDestination).
3. AttackInfo main loop (AttackInfo.cs:~436-470) per FixedUpdate tick, two parallel branches: ObservationLoop (`FindBestTarget(false)` + `CurrentFrame++`) and ActionLoop selector:
   a. `HasCombatAction()` (MeleeTarget or RangedTarget != null, or within `NoActionEndFrame = CurrentFrame + 11` after losing it) -> `DoCombatAction -> CombatActionLoop`.
   b. else `HasRunDestination()` (CanMove && Destination is SpaceLocation, or object destination with ListenToRangeInstinct/Must...) -> `StopInactiveActions`, `RunTowardDestination` (:802: `RunToward` or `WalkToward` with `precise=PreciseSearch`, `aggressive = AttackDestination != MustAttackDestination`), then `WaitForTicks(50)`.
   c. else WaitForever.
4. Melee target acquisition `FindBestTarget` (:812-835): refreshed when `CurrentFrame >= NextMeleeTargetFrame` (every 5 ticks = 0.1 s; and always forced at start), but NOT re-searched while the current target is a Labor and `WantStrike` is true (:824 -> sticky once in strike range). `FindBestMeleeTarget` (:905-960): BFS over walkable path nodes from own voxel, horizontal radius `MeleeSearchRadius` (3; 10 for MoveAttack; 2 if !CanMove), at most `MeleeSearchLimit` node expansions (30; 200 MoveAttack), accepts the first (nearest by BFS, ignores through-friendly via `PresenceTest`) enemy volume (`GetEnemiesAt`, IsValidTarget: visible for faction, not invincible). So target = nearest enemy by walking distance within 3 voxels (10 when MoveAttack). The stored path (StepBranch, NextBranch, ProjectedBranch...) gives the "step" voxels to approach.
5. Approach (DoMeleeAction :~560-640): per tick: `WantStrike` if `CharacterLocation.TargetReachedOrAcceptable(self, ownVoxel or enteringVoxel, targetVoxel)`. Melee reach in voxels (CharacterLocation.cs:~78-95): `d2 = dx^2+dz^2` (flat, integer voxel diff of the two units' voxels, entering voxel preferred if moving): reach OK if `0.81 <= d2 <= 4.41` (so d2 in {1,2,4}: orthogonal neighbour, diagonal neighbour, 2 voxels straight; NOT {5}) AND `|dy| < 1.1` AND (`d2 < 1.21` OR no obstacle between (`ObstaclePreventingAttack`, mutual liberties test on blocks/volumes)); OR `IsInVeryCloseRange` (Manhattan <= 1 and |dy| <= 1.1). Same voxel (d2=0) is NOT in range -> units never need to share a voxel to hit.
6. If not WantStrike but `WantStep` (path to enemy exists): if `CanCombatStep()` and not already in combat stance -> `Locomotion.DoFollowStrikePath(SteppingPath)` with up to 4 nodes (step, next, projected, next-projected) = a short path RUN toward the enemy re-planned every tick the BFS refreshes (every 5 ticks). If IN combat stance it first does `GetReadyToMove()` (leave stance). If `!CanCombatStep()` (CanMove false) it stays and `DoCombatTurnTo(target)` when not within 45 deg (`IsInPreferredOrientation` :899-901 uses 45 deg).
7. Strike gating (:~590-615): strike only if `IsReadyToStrike && CurrentFrame >= NextAttackFrame` and the midpoint voxel `(from+to)/2` flat equals from or to (adjacent/diagonal; 2-straight needs mid voxel pass `PassThroughDoor`: true when no closed door, so effectively always OK for 2-away). `Strike()` (:795-800) -> `Locomotion.DoStrike(target, WantStrikeFrom)`; `NextAttackFrame = CurrentFrame + RandomizedAttackCooldown` set at strike START, not at hit. If `!InCombatStance` while wanting strike: `Locomotion.Wield(null)` + `ClearPath()` (unit stops running and raises its weapon; delay = animator transition, MEASURE) and `IsPreparingToStrike = 10` ticks grace.
8. Chasing a moving target: for a Location.Of(GameObject) destination (CharacterLocation, RdvType Follow) `Navigation.NeedsRetargeting` (Navigation.cs:86-98): re-search a path (halt without stopping, wait 1 tick) when `|targetPos - targetPosAtSearch| >= max(1, ceil((distToTarget - 2)/5))`. So within 7 m: replan whenever target moved >= 1 m since last plan; 7-12 m: 2 m; 12-17 m: 3 m... The path search itself is async per tick, plus the DestinationRepathSearch local detours (below). For MoveAttack to a SpaceLocation there is no re-target: the unit runs to the fixed point and, whenever the melee BFS finds an enemy (every 5 ticks), switches to the combat approach (4-node strike path, replanned every 5 ticks) -- this is how a "chaser" tracks a mover.
9. Local repath (collision detour): `Locomotion4.RepathMoveNext` (:946-966) -> `DestinationResolver.RepathMoveNext` (DestinationResolver.cs:62-120): `DestinationRepathSearch` toward node `Current+3` (or the destination), merges with the old path, treats other units' voxels as blocked unless allied-passable. Triggered from `TryPushingForward` when the next voxel has a character (below).
10. Navigate tries/timeouts: FollowPath marks Blocked if the unit did not move >= 0.1 m for 5 s and !CanMakeWay (FollowPathRequest.cs ~:150).

## 3. Unit-unit collision / avoidance
1. NO physical collision between bricktrons while grounded. Capsule colliders exist (`RegularCollider`, CapsuleCollider.radius used only as a y offset in Airborne.cs:~32) but locomotion is kinematic code; units occupy a VOXEL (`VoxelPresence`, Volume property `VProperty.character`, VoxelPresence.cs). A unit's occupied voxel = voxel of its position; "entering" voxel = voxel of `PathIterator.CurrentActive` if different (Locomotion4.cs:254-282).
2. Blocking rule (LocomotionMovementState.GetBlocker: `GetPresenceAt(Entering).FirstOrDefault()`): before pushing forward each frame the walk/run state checks whether the ENTERING voxel contains another character volume. If yes and not (blocker==null): `RepathMoveNext()` (local detour, see 2.9); if that fails: `CanPassThroughBlocker` = `Profession.CanPassThrough()` (only Builder overrides to true, Builder.cs:160; halberdier false, Profession.cs:388) && allied; else if blocker idle (`!blocker.Locomotion.PathIterator.HasCurrent`) -> Fail (`PathBlockedAt`, path aborted -> Navigation PathInterrupted -> HaltAndWaitForInPlace, retry); else `WaitActively` (BlockedDelay 0.1 s: slide toward voxel centre by `BlockedMoveFactor 0.1`, up to `BlockedMaxCount 20` (= 2 s) then Fail).
3. Only the voxel being ENTERED is tested, not partial overlap: two units may stand 0.01 m apart if in different voxels, and mid-voxel positions are free. Enemy units also block (`CollideWithEveryone`; `DontCollideIfEnemy` = aggressive pathing ignores enemies: `BuildPresenceTest(aggressive=true)` -> units with `aggressive` (MoveAttack via RunToward(precise=PreciseSearch, aggressive = !MustAttackDestination)) plan paths THROUGH enemy voxels but still get blocked when entering). `OthersCanPassThroughMe = true` for allies only matters for Builder.
4. Body block: an unit cannot enter an occupied voxel, so a line of units on adjacent voxels blocks a corridor (Voxel granularity = 1 m; 4 neighbours). There is no separation steering/force. Stationary units (idle) permanently block and cause Fail -> re-search around them; the search treats all other characters' voxels as obstacles (PresenceTest `BlockedByAlly(p)` = any character volume at p, AttackInfo.cs:~960-980 for melee search).
5. Radius: effective collision "radius" = half a voxel (0.5 m axis-aligned cell); a unit is a point in voxel space. CapsuleCollider radius value is a prefab number (unknown, not used for movement).
6. A unit that is Flailing/stunned uses a real Rigidbody capsule on `FlailingCollider` (Common.Flailing): physical interaction only while airborne (see 5).

## 4. Walls
1. Walls are voxel blocks (5-voxel brick wall). Path nodes only exist on walkable voxels (`PathNodeRegistry`); a wall voxel is "full" -> never in a path; `IsBlockedByTerrainOrBlock = Voxel.IsFull(Entering)`. A code-driven mover cannot enter a full voxel: `PopOutOfGround` (Locomotion4.cs:1288-1303) reverts to the previous position and calls `PathBlockedAt` if "floor is occupied". `SetPosition` refuses moves > 1 voxel in a single call (Locomotion4.cs:1168-1189).
2. Because corner-cutting target = (a+2b+c)/4 stays inside the path-node hull, a unit never grazes a wall voxel along its path; wall adjacency only matters for combat reach `ObstaclePreventingAttack` (2-voxel diagonal/straight strikes need free mutual-liberty cells; blocks in between prevent the strike when d2 >= 1.21).
3. Climbing a 5 m wall is impossible without ladders/`CanClimb` + a ClimbUp node; the plateau rim therefore is an absolute boundary for pathing (units with CanMakeWay/Builder can hit-brick through it - not halberdiers).

## 5. Spawn drop, hurt reactions, striking
1. Falling: `Grounded.Update` (Locomotion/Grounded.cs): `AutoSnapToFloor` -> `CheckGrounded` each frame; if ungrounded for `TimeBeforeFalling = 0.2 s` -> `Common.Flailing.Flail()`: switches to `Airborne` (path cleared), physics Rigidbody on `FlailingCollider` (gravity; initial velocity `g * UngroundedTime`), `StunTime = now + 1 s` (Flailing.cs:315-318) when thrown/smashed, `IsStunned` cleared at StunTime-0.5 (:149). Stand-up condition: `StunTime <= now && (IsInsideGround || BodySurfing(>=1 s) || IsGrounded)` (:207). Then Stabilizing/StandingUp animator states do `MatchTargetWithY` to the nearest aligned voxel (Airborne.cs:StartStabilizing/StartStandingUp, 0.1-0.9 of clip) -> `Grounded`. Clip lengths (get-up) are animator data: MEASURE landing-stun duration (spawn height dependent: fall time + >=1 s stun + stand-up clip).
2. Hits (details docs/sim/mech-damage.md): Twitch -> `SmallHurt`: additive upper-body layer only (`Hurting.SoakSmallHurt`, ends when SoftHurt clip finished or 2 s, Hurting.IsReadyToEnd); NO movement change, NO path change, can keep running/striking. Stun -> `BigHurt` -> full Hurting state: `HurtDestination = GetNearestAligned(position)` (snap to voxel centre) and `MatchTarget(Hurting clip, 0..0.85)` = unit pinned to the voxel centre for the clip duration (MEASURE; locomotion CanMove false during Hurting animator state). Smash -> `Locomotion.Smash(contact, force, lift)` = real physics knockdown (Flailing: `AddForceAtPosition(force, origin, Impulse)` + upward `|force|*UpwardsEffect`, StunTime +1 s, then stand-up). Knight force x0.6 (BricktronDamageReceiver.cs:~340). Smash vs Stun is decided by `DoesAttackSmash` (see mech-damage).
3. Striking (Locomotion/Striking.cs): `Locomotion.DoStrike` creates `SwordStrike` (Phase Startup). Animator states: Crank (windup) -> Swing -> Reacting(Resolution). `StartCranking`: `MatchTarget(CombatCrank clip, StrikeEndPosition, orientation=LookRotation(targetFlat - strikeEnd), 0.1..0.9)`: root-motion-matched move to `StrikeEndPosition` (= `WantStrikeFrom` voxel, i.e. the voxel it intends to hit from) AND facing the target, over the crank clip 10%..90%. `StartSwinging` repeats the match for the swing clip. Damage is applied at `StartReacting` (= start of Reacting state, after crank+swing clips): `SwordStrike.Apply(target)`. So the hit lands crank+swing clip time after DoStrike (MEASURE per tick from DEV trace; do not assume; strike abort if target > 9.5 m or invalid -> `IsAbortingStrike`).
   - Striking does NOT root the unit: during Crank/Swing it is moved (matched) onto StrikeEndPosition; if that voxel becomes occupied/non-adjacent `WantsStop` (LocomotionFightingState.cs:63-67) it re-targets the current voxel with `OverrideMatchTarget(dist / CombatStepSpeed=5 m/s)`. The path is not followed during a strike (state machine is in the Fighting branch; any `FollowPath` while in combat stance calls `StopFighting` first, Fighting.cs:~26-36 / Update).
   - Facing: strike orientation = from StrikeEndPosition to target flat; achieved within the crank clip (0.1-0.9 of its length, i.e. fast: sub-second). If the target is not within 45 deg when the unit wants a combat step with CanMove false -> `DoCombatTurnTo`: `TurningTo.Enter` OverrideMatchTarget(time = angle/(360*RunTurningTopSpeed)=angle/360 s) i.e. 360 deg/s (180 deg = 0.5 s).
   - `IsReadyToStrike` is true only in the ReadyToStrike animator state (entered after combat stance raise); `IdleTimeoutDelay = 20 s` then StopFighting. After an attack the cooldown is `NextAttackFrame` (ticks, not animation).
4. A unit in combat stance that must move: `GetReadyToMove` / `Fighting.StopFighting` (IsTakingCombatStance=false) then runs - cost = animator transition (MEASURE). So run -> strike -> run cycles have transition dead time.
